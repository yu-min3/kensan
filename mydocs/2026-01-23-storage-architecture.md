# 2026-01-23 ストレージ・検索アーキテクチャ検討

## 背景

- Markdown、draw.io XMLなどのコンテンツを検索可能に保存したい
- 画像も貼りたい → オブジェクトストレージ必須
- kensan-ai（AIエージェント）との連携
- 全文検索 + セマンティック検索

---

## アーキテクチャ案

### 案A: サーバーサイド中心（PostgreSQL + pgvector + R2）

```
┌─────────────────────────────────────────────────────────┐
│  ブラウザ                                                │
│  └─ APIリクエストのみ（データはサーバーに持たない）        │
└─────────────────────────┬───────────────────────────────┘
                          │
┌─────────────────────────▼───────────────────────────────┐
│  PostgreSQL                                             │
│  ┌──────────────────┐  ┌─────────────────────────────┐  │
│  │ content (TEXT)   │  │ embedding (vector/1536)     │  │
│  │ - Markdown全文   │  │ - pgvectorでセマンティック検索 │  │
│  │ - drawio XML    │  │                             │  │
│  └──────────────────┘  └─────────────────────────────┘  │
│            +                                            │
│  tsvector (全文検索) ← ハイブリッド検索（BM25 + vector） │
└─────────────────────────────────────────────────────────┘
                          │
┌─────────────────────────▼───────────────────────────────┐
│  Cloudflare R2 / S3                                     │
│  - 画像ファイル（PostgreSQLにはURLのみ保存）              │
└─────────────────────────────────────────────────────────┘
```

**メリット**
- シンプル。既存のPostgreSQLに拡張を追加するだけ
- ハイブリッド検索（キーワード + 意味検索）が1つのSQLで完結
- マルチデバイス対応が自動的に得られる
- Supabase StorageのようなOSS実装あり

**デメリット**
- オフライン非対応
- 全データがサーバーに保存される（プライバシー懸念）

---

### 案B: Local-first（IndexedDB中心 + サーバー同期）

```
┌─────────────────────────────────────────────────────────┐
│  ブラウザ（Source of Truth）                            │
│  ┌─────────────┐  ┌────────────┐  ┌────────────────┐   │
│  │ IndexedDB   │  │ MiniSearch │  │ Sync Queue     │   │
│  │ - 全文保存   │→ │ - 検索Index│  │ - 未同期データ  │   │
│  │ - 画像Blob   │  └────────────┘  └────────────────┘   │
│  └─────────────┘                          │            │
└───────────────────────────────────────────┼────────────┘
                                            │ 同期
┌───────────────────────────────────────────▼────────────┐
│  サーバー（バックアップ + マルチデバイス同期）            │
│  ┌──────────────┐  ┌─────────────┐  ┌──────────────┐   │
│  │ PostgreSQL   │  │ pgvector    │  │ R2           │   │
│  │ (全文コピー)  │  │ (embedding) │  │ (画像)       │   │
│  └──────────────┘  └─────────────┘  └──────────────┘   │
└─────────────────────────────────────────────────────────┘
```

**メリット**
- オフライン完全対応
- 即時レスポンス（ネットワーク待ちなし）
- Dexie.jsで実装が容易
- ブラウザは数GBまで保存可能

**デメリット**
- 同期ロジックが複雑（コンフリクト解決）
- 画像を同期する場合の帯域問題
- IndexedDBの検索はMiniSearchなどのライブラリ依存

---

### 案C: ハイブリッド（検索はサーバー、編集はローカルキャッシュ）【推奨】

```
┌─────────────────────────────────────────────────────────┐
│  ブラウザ                                                │
│  ┌─────────────────┐  ┌────────────────────────────┐   │
│  │ IndexedDB       │  │ 検索はサーバーAPIを呼ぶ      │   │
│  │ - 最近のドキュメ │  │ → ハイブリッド検索          │   │
│  │   ントをキャッシュ│  │ → AI検索（kensan-ai）      │   │
│  └─────────────────┘  └────────────────────────────┘   │
└───────────────────────────────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────┐
│  サーバー（Source of Truth）                            │
│  ┌──────────────────────────────────────────────────┐   │
│  │ PostgreSQL + pgvector                            │   │
│  │ - content全文                                    │   │
│  │ - tsvector (キーワード検索)                       │   │
│  │ - embedding (セマンティック検索)                  │   │
│  └──────────────────────────────────────────────────┘   │
│  ┌────────────────┐  ┌─────────────────────────────┐   │
│  │ kensan-ai      │  │ R2                          │   │
│  │ - RAG検索      │  │ - 画像ファイル               │   │
│  │ - AIアシスタント│  └─────────────────────────────┘   │
│  └────────────────┘                                     │
└─────────────────────────────────────────────────────────┘
```

**メリット**
- バランスが良い
- 検索品質が高い（ハイブリッド + AI）
- キャッシュで体感速度向上
- kensan-aiとの連携が自然

**デメリット**
- オフラインでは検索不可（キャッシュ分のみ）
- 中途半端になるリスク

## 比較表

| 観点 | A: サーバー中心 | B: Local-first | C: ハイブリッド |
|------|----------------|----------------|----------------|
| オフライン | ✗ | ◎ | △（キャッシュのみ） |
| 検索品質 | ◎（ハイブリッド） | ○（MiniSearch） | ◎（ハイブリッド） |
| 実装難易度 | 易 | 難（同期） | 中 |
| プライバシー | △ | ◎ | △ |
| マルチデバイス | ◎ | ○（同期必要） | ◎ |
| kensan-ai連携 | ◎ | △ | ◎ |

---

## 決定事項

**案C（ハイブリッド）を採用**

理由：
1. kensan-aiとの相性が良い（RAGやAIアシスタントはサーバーサイド前提）
2. ハイブリッド検索（BM25 + pgvector）が最も精度が高い
3. 段階的に進化可能（まずサーバー中心で作り、後からIndexedDBキャッシュを追加）

画像ストレージ: **Cloudflare R2**（S3互換、egress無料）
