## 各技術の役割と選定理由

### 1. React 18 - UIコンポーネントフレームワーク

| 項目 | 内容 |
|------|------|
| **役割** | UIコンポーネントの構築、仮想DOMによる効率的な描画 |
| **使用箇所** | 全てのUIコンポーネント |
| **選定理由** | エコシステムの充実、TypeScriptとの親和性、Concurrent Featuresによるパフォーマンス |

```
React 18 の主な利点
├── Concurrent Rendering（並行レンダリング）
│   └── 重い処理中もUIがブロックされない
├── Automatic Batching（自動バッチング）
│   └── 複数のstate更新を1回のレンダリングにまとめる
└── Suspense の改善
    └── データフェッチ時のローディング状態管理
```

### 2. TypeScript - 型安全性

| 項目 | 内容 |
|------|------|
| **役割** | 静的型チェック、コード補完、リファクタリング支援 |
| **使用箇所** | 全ソースコード（`.ts`, `.tsx`） |
| **選定理由** | 大規模アプリでのバグ防止、開発効率向上、ドキュメントとしての型定義 |

```typescript
// 型定義の例（src/types/index.ts より）
export interface TimeBlock {
  id: string
  date: string           // YYYY-MM-DD
  startTime: string      // HH:mm
  endTime: string        // HH:mm
  taskName: string
  goalTag?: GoalTag      // Optional
  isRoutine: boolean
}
```

### 3. Vite - ビルドツール

| 項目 | 内容 |
|------|------|
| **役割** | 開発サーバー、本番ビルド、HMR（Hot Module Replacement） |
| **使用箇所** | 開発・ビルドプロセス全体 |
| **選定理由** | 高速な起動（ESModulesベース）、シンプルな設定、Rollupベースの最適化ビルド |

```
Vite vs 従来のバンドラー（Webpack等）
┌─────────────────────────────────────────────────────────────┐
│ 従来（Webpack）                                              │
│ [全ファイル] → [バンドル] → [開発サーバー起動]               │
│              時間がかかる                                    │
├─────────────────────────────────────────────────────────────┤
│ Vite                                                        │
│ [開発サーバー即起動] → [必要なファイルのみオンデマンド変換]  │
│  高速！                                                     │
└─────────────────────────────────────────────────────────────┘
```

### 4. Tailwind CSS v4 - ユーティリティファーストCSS

| 項目 | 内容 |
|------|------|
| **役割** | スタイリング、レスポンシブデザイン、ダークモード対応 |
| **使用箇所** | 全コンポーネントのクラス名 |
| **選定理由** | 高速な開発、一貫したデザイン、CSSファイル肥大化防止 |

```tsx
// Tailwind CSS の使用例
<div className="flex items-center gap-4 p-4 rounded-lg bg-muted/50 hover:bg-muted">
  {/* flex: フレックスボックス */}
  {/* items-center: 垂直方向中央揃え */}
  {/* gap-4: 子要素間の余白 */}
  {/* p-4: パディング */}
  {/* rounded-lg: 角丸 */}
  {/* bg-muted/50: 背景色（50%透過） */}
  {/* hover:bg-muted: ホバー時の背景色 */}
</div>
```

### 5. shadcn/ui - UIコンポーネントライブラリ

| 項目 | 内容 |
|------|------|
| **役割** | 再利用可能なUIコンポーネント（Button, Card, Dialog等） |
| **使用箇所** | `src/components/ui/` 配下 |
| **選定理由** | コピペ方式でカスタマイズ自由、Radix UIベースのアクセシビリティ、Tailwindとの統合 |

```
shadcn/ui の特徴
├── コピペ方式
│   └── node_modules ではなく自分のプロジェクトにコードをコピー
│   └── 完全にカスタマイズ可能
├── Radix UI ベース
│   └── アクセシビリティ（キーボード操作、スクリーンリーダー対応）
│   └── ヘッドレスコンポーネント（見た目は自由）
└── CSS Variables による テーマシステム
    └── ダークモード対応が容易
```

### 6. Zustand - 状態管理

| 項目 | 内容 |
|------|------|
| **役割** | グローバルな状態管理（ストア） |
| **使用箇所** | `src/stores/` 配下の各ストア |
| **選定理由** | シンプルなAPI、ボイラープレート少、TypeScript親和性、パフォーマンス |

```
状態管理ライブラリ比較
┌────────────┬─────────────┬──────────────┬─────────────┐
│            │   Redux     │   Zustand    │   Jotai     │
├────────────┼─────────────┼──────────────┼─────────────┤
│ 学習コスト │    高       │     低       │     低      │
│ ボイラー   │    多       │     少       │     少      │
│ DevTools   │    ◎       │     ○       │     ○      │
│ 適用規模   │   大規模    │   中〜大規模  │   小〜中規模 │
└────────────┴─────────────┴──────────────┴─────────────┘

Kensan では Zustand を採用 → 適度な機能とシンプルさのバランス
```

### 7. React Router v6 - ルーティング

| 項目 | 内容 |
|------|------|
| **役割** | クライアントサイドルーティング、画面遷移 |
| **使用箇所** | `src/App.tsx` のルート定義、各画面からの`Link`/`navigate` |
| **選定理由** | デファクトスタンダード、Nested Routes、Data APIs |

### 8. Recharts - グラフライブラリ

| 項目 | 内容 |
|------|------|
| **役割** | データ可視化（棒グラフ、円グラフ、折れ線グラフ） |
| **使用箇所** | ダッシュボード、分析画面 |
| **選定理由** | Reactネイティブ、宣言的API、カスタマイズ性 |

### 9. date-fns - 日付操作

| 項目 | 内容 |
|------|------|
| **役割** | 日付のフォーマット、計算、ロケール対応 |
| **使用箇所** | 日付表示全般 |
| **選定理由** | Tree-shaking対応（軽量）、immutable、日本語ロケール対応 |

### 10. Lucide React - アイコン

| 項目 | 内容 |
|------|------|
| **役割** | UIアイコン表示 |
| **使用箇所** | 全画面のアイコン |
| **選定理由** | 軽量、Tree-shaking対応、一貫したデザイン |
